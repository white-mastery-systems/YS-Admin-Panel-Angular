Angular Upgrade Plan: v16 → v21

YS-Admin-Panel-Angular (YourStore Admin) — one major at a time, separate branch per hop, merge into dev.

CURRENTAngular 16.2.12
TARGETAngular 21 (LTS)
BASE BRANCHdev
PATH16 → 17 → 18 → 19 → 20 → 21
Is Angular 21 okay? Yes. Angular 21 is a supported LTS target. It is a better end goal than jumping straight to 22 right now, and it keeps you on a maintained release without adopting Angular 22’s newer defaults yet.

2. Environment prep (before any hop)

git checkout dev
git pull origin dev

node -v
npm -v

rm -rf node_modules
npm ci
npx ng version
npx ng build
Use Node 20 LTS or Node 22. Do not start the next hop until build + smoke tests pass and the previous hop is merged into dev.
  • ng build succeeds
  • App starts (npm start)
  • Critical smoke tests pass (login, store list, orders, settings)
  • Branch merged into dev
  • Local dev updated from remote

3. Standard workflow for EVERY major hop

Replace NN with 17, 18, 19, 20, or 21.

git checkout dev
git pull origin dev
git checkout -b chore/angular-upgrade-vNN

npx ng update
npx ng update @angular/core@NN @angular/cli@NN
npx ng update @angular/localize@NN @angular/service-worker@NN

npm install
npx ng build
npm start
# smoke-test, then stop server

git add .
git commit -m "chore(angular): upgrade to vNN"
git push -u origin chore/angular-upgrade-vNN

gh pr create --base dev --head chore/angular-upgrade-vNN \
  --title "chore(angular): upgrade to vNN" \
  --body "## Summary
- Upgrade Angular to vNN

## Test plan
- [ ] ng build
- [ ] smoke test critical screens"

# After approval:
gh pr merge --merge
git checkout dev
git pull origin dev

ngx-bootstrap / @ng-bootstrap/ng-bootstrapBump to matching Angular major
ngx-echarts / ng-apexcharts / ngx-quillBump compatible version
tslint / codelyzer / protractorRemove during early hops
Capacitor 4Fix in a follow-up PR if mobile build breaks

7. What NOT to do

  • Do not skip majors (e.g. 16 → 19 directly)
  • Do not rewrite to standalone in the same PR as a version hop
  • Do not enable zoneless change detection yet
  • Do not merge if ng build fails
  • Do not start hop N+1 from an unmerged hop N branch — always branch from updated dev
